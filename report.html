判讀

① 09/22 至 07:40 零降雨;土城改用環域值 確認無雨

七地環域站數分別是 12、11、13、7、7、4、4,合計 58 站次,全部回報 0.0 mm。環域站數都大於 0,代表每一地都有實際測站在回報:這是「0 / N」——N 站確認無雨;與「env_n = 0」(查無資料)意思相反,本次七地皆屬前者。

土城區要分開講。它的代表站就是缺測的那一站(C0AD40 土城),summarize 回的 rep_value 是 null 而不是 0。因此卡片的代表站欄位寫「未取得」,該地實測一律改用環域 7 站的值。附帶一提,verdict() 這時吐的字串是「環域 7 站全 0(含代表站)」,「含代表站」在這個情境下並不成立——代表站是沒資料,不是報 0,判讀時不要照抄。

本日累積(RainfallElement.Now)在 46 站全為 0.0 mm,意思是09/22 00:00 起到 07:40 為止,取得到的站沒有任何一站錄到降雨。

判讀今晨七地沒有降雨,依據是 58 站次的環域實測。土城的數字來自環域而非代表站,已在卡片上標明。新竹與竹北已進入強風特報效期,效期到明(23)晚。

② 雨帶移動方向:本次不准寫 不可判讀

第三道守門觸發。track() 回 confidence: none,note 為「目前 10 分鐘內範圍內無站有雨,無法定位雨區」;now_centroid 與 prev_centroid 都是 null。

守門規則是 track 回 unusable 或 none 就不准寫雨往哪移動。這兩種成因不同:unusable 是雨區消散讓質心位移變成假象,none 是根本沒有雨可以定位。本次是後者。

判讀本報告不提供任何降雨移動方向與速度。連「雨在減弱、殘留在哪幾站」都無從寫起——沒有殘留站。

③ 強風特報改發新版,效期延到 09/23 範圍已變更

今晨 04:35 發布的是新的一則強風特報,不是昨日那則的延續:成因寫法由「風力偏強」改為「東北風偏強」,效期由 09/22 23:00 延長到 09/23 23:00,縣市名單拿掉嘉義縣。

把昨天到今晨合起來看,這類特報在 24 小時內出了四份不同名單:09/21 04:32(無新竹)→ 10:26(加入新竹市、新竹縣)→ 19:43(再加雲林、臺東含蘭嶼)→ 09/22 04:35(改為東北風、去嘉義、效期延一天)。新竹市與新竹縣自 10:26 起每一版都在內。

判定用 areas_ours 而非 areas_near:本次 areas_ours 命中「新竹」,areas_near 命中桃園與苗栗。若只看 areas_near,會把桃園苗栗的命中誤讀成本區有特報;而 09/21 04:32 那版新竹夾在桃園與苗栗中間卻不在範圍內,正是不能用鄰區推本區的原因。

判讀一律以最新一則的實際縣市名單與效期為準。本次要改的不只是名單,還有效期——強風風險已延長到 09/23 晚上,比昨天那版多一天。

④ 09/21 確認無雨的區間是 00:00–21:40,不是整日到午夜 跨時間比對

09/21 共九筆快照(00:30 至 21:40 觀測),全站網本日累積始終為 0.0 mm。但排程最後一輪在 21:40,21:40 到午夜這兩小時二十分沒有快照覆蓋,而 now 跨日會歸零,事後無法回補。因此嚴謹的說法是「09/21 00:00–21:40 經 47 站確認無降雨」,而不是「整日無雨」。

09/22 這筆的本日累積在 07:40 為 0,只能說明今日凌晨到早上沒下,不能反推昨夜 22–24 時的狀況。昨夜那段就是未觀測,不是已確認無雨。

判讀這是上一份報告標題用「完整乾日」時略微超出資料範圍的地方,此處修正。取不到就標未取得——時間上的缺口與空間上的缺測站一樣,不補、不外推。

⑤ yr.no 把 09/30 從 0 改成 46.9 mm,第 9 天完全不可用 低雨量期

昨晚 21:54 那版,09/30 是剛進入預報窗的最後一天,七地全部 0 mm。今晨 07:51 這版把同一天改成:台北 46.9、板橋中和 43.8、土城樹林 32.0、新竹竹北 13.4 mm。09/29 也由台北 3.4 升到 6.4、板橋中和 1.9 升到 4.6。

同一天的預報值在 10 小時內由 0 跳到 46.9 mm。這是「不可當預報值引用」最直接的證據,不是模式在收斂,而是第 8–9 天本來就沒有可用解析度。這裡如實記下數字,但不據此宣告 09/29–09/30 會下大雨;同樣地,昨晚那個 0 也不該當成不會下。

可以講的是傾向:連續兩版都把月底前後指為這段乾期可能結束的時間點,方向一致、量級無意義。近三天(09/22–09/24)兩版都是 0,這部分才穩定。氣象署鄉鎮 3 小時降雨機率(07:51 取得,涵蓋 07–12 時)七地全部 0%,天況全晴。

判讀今明兩日可以放心:實測無雨、PoP 0%、模式 0 mm,三者一致。09/29–09/30 的數字只看方向不看量——一個在 10 小時內從 0 變 46.9 的值,不具備規劃用途,下次更新很可能再變。

⑥ 石碇淡水已回補,本次換土城缺測 據實標示

C0A640(石碇)與 466900(淡水)本次都正常回報。改為 C0AD40(新北土城,edge 盆地邊緣)未取得,是本次唯一缺測站。近四輪的缺測站各不相同,屬個別站的間歇性中斷,不是系統性失效。

影響有兩層:terrain_split 的邊緣樣本由 11 站降為 10 站;土城區的代表站因此沒有值,該地實測改用環域 7 站。板橋、中和、樹林的環域也各少 1 站(12→11、14→13、8→7),因為土城站落在它們的 9 km 內。

判讀缺測站一律排除,不以 0 補、也不以鄰站內插。當缺的剛好是某地的代表站時,該地的代表站欄位寫「未取得」、實測改用環域值——這正是第一道守門「實測欄位一律用環域值」要處理的情況。

資料來源與方法

抓取、空間分析、判讀、產生報告都在 Claude session 內完成,GitHub 只負責部署。
  • 實測:氣象署開放資料 API O-A0002-001,46 / 47 站取得,C0AD40(土城)缺測已排除、未以 0 補;該站是土城區的代表站,故土城區代表站欄位標「未取得」,實測改用環域值。觀測時刻 07:40(API 提供 ObsTime),抓取 07:50。
  • 數值語意:卡片上的 mm 是 RainfallElement.Now,即本日累積雨量;p10 / p1h 另存於快照,供 track() 估質心用。
  • 環域半徑 9 km,七地合計 62 站次。「0 / N」是 N 站確認無雨;「env_n = 0」才是查無資料。本次七地皆屬前者。
  • 三道守門:代表站漏接未觸發(環域也全 0,無漏接可言);terrain_split 未觸發(無明顯地形分離);track 已觸發(confidence none,不寫移動方向)。
  • 特報保留全部中文特報,再標 areas_ours 與 areas_near 兩份清單。本次 areas_ours 命中新竹(04:35 強風特報新版),故判定涵蓋本區;areas_near 命中 0。另一則標題含「大雨特報」者實為解除訊息,已據語意標為已解除,未當成生效中的特報。
  • 缺漏一律標「未取得」,不以鄰區數值代填、不內插、不編造。
